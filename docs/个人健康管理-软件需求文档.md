## 1. 背景与目标

### 1.1 背景

个人健康数据分散在体检纸质报告、手机相册、手写记录和各个设备 App 里。用户想随手记下血压、体重、血糖等关键指标，却缺少一个能在电脑和手机上连续使用的地方；体检报告存下来之后也很难和日常指标放在一起看。与此同时，用户需要的不是又一个资讯信息流，而是能按主题学完、能回头复习的健康知识，以及基于**自己的数据**给出的、可追溯的建议。

本产品面向个人自用，把「记下来、管起来、看明白、养成习惯、系统学习」放在同一个账户里。

### 1.2 产品目标

1. 同一账户在 PC 浏览器和手机浏览器上都能完整使用，数据一致。两端各自按屏幕重新排版，界面美观、小清晰。
2. 关键健康指标可以即时记录，并按时间查看、对比和管理。
3. 体检报告可以上传、归档、检索，并尽量结构化，方便和日常指标对照。
4. 大模型可以基于用户授权的指标、报告和学习记录做分析，给出可追溯的生活建议与就医提示。
5. 健康习惯可以设定、提醒和打卡，并看到连续完成情况。
6. 健康知识按分类和专题组织，支持从一条小 tips 进入一条可跟踪进度的学习路径。

### 1.3 成功标准（上线后 8 周，个人可用产品的观察口径）

以下用于版本复盘，不作为上线门禁的硬性运营指标：

- 新用户能在 3 分钟内完成基础档案，并成功记下至少 1 条指标。
- 手机端完成一次「记录指标」不超过 3 步（不含登录）。
- 一份 PDF 或图片报告可在上传后进入可管理状态；解析失败时仍可手动归档。
- 用户能对「近 30 天某指标」或「某一份报告」发起一次分析，并看到依据来自哪些记录。
- 用户能创建习惯、完成当日打卡，并在次日看到连续天数。
- 用户能进入一个专题，读完至少一篇，进度被记住。

### 1.4 产品原则

- **个人数据优先。** 默认只服务当前登录用户，不设公开动态、不设陌生人社交。
- **记录要短，管理要全。** 手机端强调随手记；PC 端强调看趋势、核对报告、系统学习。
- **界面小清晰。** 两端都好看、好读。信息块紧凑，数字、单位和状态一眼能分清，装饰少，留白均匀。详见 4.4。
- **建议必须可追溯。** 每条分析都标明使用了哪些指标、哪份报告、哪个时间范围。
- **建议不是诊疗。** 产品提供健康信息与生活建议，不提供诊断、不开具处方、不替代医生。
- **敏感信息单独同意。** 健康数据上传、以及把数据发送给大模型，都需要用户明确授权，且可关闭、可删除。

## 2. 范围

### 2.1 本期包含（V1.0）

| 模块 | 本期能力 |
| --- | --- |
| 多端适配与视觉 | 响应式 Web：PC、平板、手机浏览器各自排版；界面美观、小清晰；手机可「添加到主屏幕」（PWA） |
| 账户与档案 | 注册登录、基础健康档案、隐私与授权设置 |
| 健康指标 | 预置关键指标、自定义指标、即时记录、历史管理、趋势图、参考区间提示、记录提醒 |
| 体检报告 | 图片 / PDF 上传、归档、检索、预览；大模型或 OCR 辅助提取；人工核对；可选写入指标曲线 |
| 大模型分析 | 指标解读、单报告解读、综合周报/月报、追问；危急情况提示就医 |
| 习惯打卡 | 模板与自定义习惯、打卡、补卡、提醒、连续天数与完成率 |
| 健康学习 | 分类、专题路径、文章、每日一条 tips、收藏、学习进度 |

### 2.2 本期不包含

- 在线问诊、挂号、药品销售、保险理赔。
- 家庭成员共享档案、医生端、企业健康管理后台。
- 可穿戴设备与医院系统的自动同步（列入后续版本）。
- 社区发帖、排行榜、公开分享个人健康数据。
- 由模型直接修改用户的指标或报告原文。模型只生成建议和待确认的提取结果。

### 2.3 后续版本方向（不在 V1.0 承诺内）

- 蓝牙 / 健康平台数据导入（Apple 健康、华为运动健康等，以实际可接入范围为准）。
- 多报告同指标自动对比视图的增强（V1.0 先做基础对比）。
- 家庭账户只读共享。
- 导出 PDF 健康摘要，便于就诊时给医生看。

## 3. 用户与场景

### 3.1 目标用户

单一用户类型：**关注自身健康的成年人**，自己记录、自己查看。典型差异只在使用端，不拆成多套产品。

| 使用方式 | 典型时刻 | 产品应优先满足 |
| --- | --- | --- |
| 手机 | 晨起称重、饭后测血糖、体检完拍报告、碎片时间看一条知识 | 大按钮、少步骤、可单手完成、提醒准时 |
| PC | 周末整理近三个月血压、核对体检提取结果、顺着专题学完一章 | 宽表、大图、并排对照、长文阅读 |

基础档案采集性别、出生日期、身高，仅用于 BMI、部分参考区间和内容排序。用户可拒绝填写非必要项；拒绝后相关计算显示「资料不足，暂不计算」，其余功能仍可用。

### 3.2 关键场景

**场景 A：随手记一条血压**

早上测完血压，打开手机，在首页点「记一笔」，选择血压，填收缩压、舒张压、心率（可选）和测量时间，保存。首页卡片和趋势图立刻更新。若数值落在产品配置的「建议尽快就医」区间，页面同时给出固定文案的就医提示，不展开居家处置步骤。

**场景 B：电脑上回顾一个月**

在 PC 打开指标页，筛选「血压 / 近 30 天」，看到折线、均值、最高最低，以及每条原始记录。可改一条记错的数据，改动写入操作记录。

**场景 C：上传并读懂体检报告**

手机拍下报告或在电脑上传 PDF。报告进入列表，可预览原件。系统尝试提取日期、机构、检查项和结果；用户在「待核对」里改正错误项并确认。确认后，用户可选择把部分数值（如空腹血糖、低密度脂蛋白）写入对应指标的历史，来源标记为「体检报告」。

**场景 D：让模型基于自己的数据提建议**

用户点击「分析近 30 天血压」或「解读这份报告」。分析前展示将使用的数据范围，用户确认后才发送。结果包含：观察到的事实、生活建议、建议咨询医生的情况、依据列表。用户可以追问，追问仍限制在已授权数据内。

**场景 E：习惯打卡**

用户从模板打开「23:30 前放下手机」，设置提醒。到点收到提醒，点一次即完成。首页展示今日待打卡；习惯页展示连续天数和本月完成率。

**场景 F：按专题学习**

用户从「今日一条」进入《读懂体检报告》专题，按顺序阅读，进度自动保存。学完一节后看到下一节；也可只收藏、稍后在 PC 上继续。分类浏览和搜索始终可用。

## 4. 总体方案

### 4.1 多端策略

V1.0 采用**一套响应式 Web**，覆盖 PC 与手机浏览器，并支持 PWA，使用户可以把产品添加到手机主屏幕、在本地收到提醒（受浏览器和操作系统能力限制，需在首次开启提醒时说明）。

不在 V1.0 单独开发 iOS / Android 原生 App。交互按端适配，而不是把 PC 页面等比缩小。

| 维度 | 手机（宽度 &lt; 768px） | 平板（768–1023px） | PC（≥ 1024px） |
| --- | --- | --- | --- |
| 导航 | 底部 5 个一级入口 | 底部或可收起侧栏 | 左侧固定导航 |
| 首页 | 单列卡片，主操作固定在拇指区 | 双列卡片 | 左概览 + 右趋势/待办 |
| 记录指标 | 底部全屏表单或半屏面板 | 居中对话框 | 右侧抽屉或对话框，背后保留图表 |
| 趋势图 | 默认同屏 1 个指标，可左右切换 | 1–2 个 | 可并排 2 个，表格在图下方 |
| 报告 | 列表 + 全屏预览 | 列表 + 预览 | 左列表、右预览与提取结果 |
| 学习 | 单列文章，底部进度 | 目录可折叠 | 左目录、右正文 |
| 触控 | 可点区域高度 ≥ 44px | 同左 | 鼠标悬停仅作补充，所有操作可点击完成 |
| 文字 | 正文 ≥ 16px | 正文 ≥ 16px | 正文 ≥ 14px，长文行宽约 66 个汉字 |

通用要求：

- 断网时：已打开过的首页缓存可看；新的记录先保存在本机，网络恢复后自动同步，并标记同步状态。冲突时保留两端版本，请用户选择（同一条记录被两台设备同时修改时）。
- 登录态在同一浏览器保持；退出登录后清除本机缓存中的健康数据。
- 横屏手机：底部导航仍可用，图表可横向铺开，不强制用户转回竖屏。
- 关键流程在 320px 宽下不出现横向滚动（图表内部滚动除外）。
- 支持系统深色模式。健康状态色不单独依赖红绿色区分，同时使用文字标签（如「偏高」「在参考范围内」）。
- 视觉质量见 4.4。布局适配和外观一起验收，只做到「能用」不算完成。

### 4.2 信息架构

```text
首页
  ├─ 今日指标摘要
  ├─ 今日待打卡
  ├─ 今日一条
  └─ 分析入口
指标
  ├─ 指标看板
  ├─ 记一笔
  ├─ 单指标趋势与记录明细
  └─ 自定义指标
报告
  ├─ 报告列表与筛选
  ├─ 上传
  ├─ 原件预览
  └─ 提取结果核对
分析（也可从首页、指标、报告进入）
  ├─ 选择数据范围
  ├─ 分析报告
  └─ 历史分析与追问
习惯
  ├─ 今日
  ├─ 习惯管理
  └─ 统计
学习
  ├─ 今日一条
  ├─ 分类
  ├─ 专题路径
  ├─ 文章
  └─ 收藏与进度
我的
  ├─ 健康档案
  ├─ 提醒
  ├─ 隐私与授权
  ├─ 数据导出 / 删除
  └─ 关于与免责声明
```

手机底部导航：**首页、指标、报告、习惯、学习**。「分析」从首页和上下文进入，不占底部一级位置。「我的」放在首页右上角。

PC 左侧导航：首页、指标、报告、分析、习惯、学习、我的。

### 4.3 全局规则

- 时间默认使用用户本地时区，存储使用 UTC，展示换算回本地。
- 数值输入使用用户常用单位，并在档案中记住单位偏好（体重 kg、身高 cm、血糖 mmol/L、体温 ℃）。V1.0 不做英制切换。
- 删除使用二次确认。健康记录删除后进入 30 天回收站，可恢复；到期后物理删除。用户在「删除账户」时立即进入删除流程（见第 10 章）。
- 所有写操作记录操作者与时间。V1.0 只有本人。

### 4.4 界面视觉：美观、小清晰（P0）

PC 和手机是两套完整界面，共用同一套组件和视觉语言，按屏幕重新组织信息。手机页由 PC 页缩小得到，或 PC 页只是手机页拉宽，都不算适配完成。

**美观**指全站像同一个产品：颜色、字号、圆角、间距、图标来自同一套规范，页面安静、对齐稳定。

**小清晰**指信息精致、轻量、一眼可读：

- 区块小而完整。一张卡片只讲一件事，例如最近一次血压、今日待打卡、今日一条。
- 层级少。全站字号不超过四级：页面标题、区块标题、正文、辅助说明。指标数字是该区块里最清楚的元素，单位、时间、状态贴在数字旁，字号更小、颜色更轻，仍然可读。
- 留白均匀，同类间距全站一致，使用 4px 的倍数。卡片之间、卡片内部的留白成套，不靠加大色块填充空白。
- 装饰少。图标线性、尺寸统一。插图只用于空状态和引导，数据页以数字和文字为主。
- 动效短，约 150–250ms，只用于保存成功、展开、切换等状态变化。

具体要求：

| 编号 | 要求 |
| --- | --- |
| UI-01 | 建立一份设计基线：主色 1 个、中性色阶、状态色（参考范围内 / 需要关注 / 建议就医）、圆角、阴影层级（扁平为主，最多一层轻阴影）、间距刻度、字号四级。浅色与深色使用同一套语义。 |
| UI-02 | 状态同时用颜色、文字标签表达。色值对比满足：正文相对背景至少 4.5:1，大号指标数字至少 3:1。 |
| UI-03 | 手机竖屏一次只突出一个主操作。底部导航和系统安全区不遮挡主按钮、最后一条内容或输入框；键盘弹出时当前输入项保持可见。 |
| UI-04 | 手机卡片最多两层（页面上的卡片，卡片内不再套卡片）。列表行高足够单手点按，可点区域高度 ≥ 44px。 |
| UI-05 | PC 内容区有最大宽度，宽于 1440px 时居中，正文行宽保持易读。表格用于明细，卡片用于摘要，同一信息在 PC 上仍保持小块、清楚，不拉成横跨全屏的空条。 |
| UI-06 | 图表在两端都完整显示坐标、单位、图例和时间范围。手机默认同屏一张图；点可以点中，数字不被裁切。 |
| UI-07 | 必须检查的宽度：320、390、768、1024、1280、1440。每个宽度下导航、标题、主按钮、表单、图表完整可见，文字不重叠、不溢出卡片、不被截断成无法理解的半个词。 |
| UI-08 | 横竖屏切换、分屏、浏览器缩放至 100% 与 125% 时重新排版。页面本身不出现横向滚动；图表和宽表可以在自身区域内横向滚动。 |
| UI-09 | 每个主页面的加载、空、失败状态使用同一套组件，文案和主操作齐全，布局不跳动。 |
| UI-10 | 新页面进入开发前，先有该页的手机稿和 PC 稿。验收时两种宽度都要看，缺一端稿子视为该页未完成。 |

## 5. 功能需求

优先级约定：

- **P0**：V1.0 上线必须具备。
- **P1**：V1.0 应做；若排期不够，可放到紧随其后的小版本，但需求保持有效。
- **P2**：明确不做进 V1.0，仅记录方向。

需求编号前缀：`ACC` 账户，`MET` 指标，`RPT` 报告，`AI` 分析，`HAB` 习惯，`LRN` 学习，`SYS` 跨端与系统。

### 5.1 账户与健康档案

#### ACC-01 注册、登录、退出（P0）

- 支持手机号验证码登录；验证码 60 秒内不可重发，单日单号发送有上限。
- 支持密码登录作为同一手机号的补充方式，密码不少于 8 位，且同时包含字母和数字。
- 提供退出登录。退出后本机不再保留指标、报告文件、分析和习惯数据。
- 连续失败锁定与具体风控阈值由安全方案确定，产品要求：不能在无提示的情况下永久锁死用户。

#### ACC-02 基础档案（P0）

字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 昵称 | 否 | 默认「用户」+ 手机号后 4 位 |
| 出生日期 | 否 | 用于年龄相关提示，不公开展示 |
| 性别 | 否 | 女 / 男 / 不便透露。仅影响有性别差异的参考区间 |
| 身高 | 否 | cm，用于 BMI |
| 单位偏好 | 是 | 有默认值 |

- 首次登录用不超过 3 步的引导完成档案，每一步可跳过。
- 档案可随时在「我的」修改。身高变更不回写历史 BMI；历史 BMI 按记录当时的身高计算，若当时没有身高则该条不计算 BMI。

#### ACC-03 参考区间说明（P0）

- 预置指标的参考区间来自产品配置的公开常识范围，页面固定展示：「参考区间仅供个人记录对照，不能作为诊断依据。」
- 用户可为某个指标设置「我的目标区间」，目标区间与通用参考区间同时显示，图例必须能区分。

### 5.2 健康指标

#### MET-01 预置指标（P0）

V1.0 预置以下指标。每条记录都有：测量时间（默认为当前时间，可改）、备注（选填，200 字）、来源（手动 / 体检报告）。

| 指标 | 记录字段 | 默认参考区间（成人常识范围，可配置） |
| --- | --- | --- |
| 体重 | 体重 kg | 不设统一「正常」，展示 BMI |
| BMI | 由体重和当时身高计算，不可单独手填 | &lt; 18.5 偏低，18.5–23.9 参考范围，24.0–27.9 超重，≥ 28.0 肥胖。采用中国成人常用划分，并在界面注明口径 |
| 腰围 | cm | 男性 ≥ 90、女性 ≥ 85 标记为需要关注；性别未知时只展示数值 |
| 血压 | 收缩压、舒张压 mmHg，心率可空 | 收缩压 ≥ 140 或舒张压 ≥ 90 标记偏高；收缩压 ≥ 180 或舒张压 ≥ 120 标记为建议尽快就医 |
| 静息心率 | 次/分 | &lt; 50 或 &gt; 100 标记需要关注（运动后测量不适用，备注中可标明） |
| 血糖 | 数值 mmol/L + 场景（空腹 / 餐后 2 小时 / 随机 / 睡前） | 按场景使用不同区间，区间写入配置并在表单上可见 |
| 体温 | ℃ | ≥ 37.3 标记发热；≥ 39.0 标记建议就医 |
| 血氧饱和度 | % | &lt; 95 标记需要关注；&lt; 90 标记建议尽快就医 |
| 睡眠 | 入睡时间、起床时间，或直接填时长（小时，允许 1 位小数） | 时长 &lt; 6 或 &gt; 9 仅作「偏离常见范围」提示，不下结论 |
| 饮水量 | ml，可一天多条，按自然日汇总 | 用户可设每日目标，默认 1500 ml |
| 步数 | 步，按自然日一条，重复记录则更新当日值并保留修改记录 | 用户可设每日目标，默认 8000 |
| 症状备忘 | 文本 500 字 + 可选部位标签（头、胸、腹、四肢、其他） | 不设数值区间 |

「实时记录」在本产品中的定义：

- 用户提交后，**1 秒内**在当前设备的列表、首页摘要和趋势图中可见。
- 其他已登录设备在网络正常时 **5 秒内**看到同一条记录；做不到推送时，进入页面即拉取最新数据，下拉刷新必须可用。
- V1.0 不要求接入医疗设备的连续波形或秒级采集。

#### MET-02 记一笔（P0）

- 入口：首页主按钮、指标页、单指标页。
- 最近使用的 4 个指标排在选择器前面。
- 校验：必填字段为空不可提交；数值超出物理可能范围时阻止保存并说明（例如收缩压不在 40–260）。超出参考区间但落在物理可能范围内时允许保存，并在保存后展示状态标签。
- 测量时间不能晚于当前时间 5 分钟以上（允许轻微时钟误差）。
- 血压的收缩压必须大于舒张压。
- 保存成功有明确反馈，并停留在可继续记下一笔的状态。

#### MET-03 看板与趋势（P0）

- 指标看板展示每个预置指标的最近一条值、测量时间、相对参考区间或目标的状态。
- 单指标页包含：折线图、时间范围（7 天 / 30 天 / 90 天 / 全部）、均值、最高、最低、记录次数。
- 血糖按场景筛选，避免把空腹和餐后画成一条没有区分的线。图例或颜色以外，必须能从标签看出场景。
- 点选图上的点，定位到对应记录。
- 无数据时展示引导记录，不展示空坐标轴冒充有数据。

#### MET-04 记录管理（P0）

- 可编辑、删除单条记录。编辑后重新计算派生值（如 BMI）和状态标签。
- 列表展示来源。来源为体检报告的记录，可跳回原报告。
- 支持按指标、时间范围筛选。PC 端用表格，手机端用时间分组列表。

#### MET-05 自定义指标（P1）

- 用户可新增数值型或文本型指标：名称、单位、可选目标上下限、每天是否允许多条。
- 自定义指标出现在「记一笔」和看板中。
- 可停用。停用后不再出现在记一笔列表，历史仍可查。
- 预置指标不可删除，可在看板中隐藏。

#### MET-06 记录提醒（P1）

- 用户可为某个指标设置提醒：每周哪些天、什么时间、提醒文案。
- 提醒只负责打开记录页并带上该指标，不自动写入数值。
- 权限未开时，在设置页说明如何开启，并保留应用内的「今日待记录」列表作为兜底。

### 5.3 体检报告

#### RPT-01 上传（P0）

- 格式：PDF、JPG、JPEG、PNG、HEIC。HEIC 在服务端转为可预览格式，原件仍可下载。
- 单文件上限 20 MB。一次最多 10 个文件。手机支持拍照和从相册选择；PC 支持拖拽上传。
- 上传过程显示进度，可取消未完成的文件。失败可重试，已成功的文件不回滚。
- 每份报告的用户字段：标题（默认识别到的体检日期或文件名）、体检日期、体检机构（选填）、类型（年度体检 / 化验单 / 影像报告 / 其他）、备注。
- 类型和日期可由提取结果预填，用户可改。

#### RPT-02 列表、预览、管理（P0）

- 按体检日期倒序。可按年份、类型、关键词（标题、机构、备注）筛选。
- 预览：图片直接看；PDF 在页内预览。提供下载原件。
- 可编辑元数据、删除报告。删除报告时，询问是否同时删除「由该报告写入」的指标记录，默认不删除，只解除来源跳转。
- 报告文件仅本人可访问。分享链接不在 V1.0 提供。

#### RPT-03 内容提取与核对（P0）

- 上传完成后自动开始提取。状态：上传中、解析中、待核对、已核对、解析失败。
- 提取目标字段：体检日期、机构、项目名称、结果、单位、报告自带参考范围、异常标记（若报告上有箭头或文字）。
- 解析失败时报告仍保留，状态为「解析失败」，用户可手动把报告标为已归档，或逐条手填项目。
- 待核对页：左（或上）原件，右（或下）提取表格。用户可改、删、增行。
- 用户点击「确认无误」后状态变为已核对。未确认的提取结果**不能**被大模型当作已核实事实；模型若使用未核对结果，必须在依据里标明「未经你确认的提取结果」。
- 默认分析只使用已核对项目。用户可显式勾选「包含未核对提取」.

#### RPT-04 写入健康指标（P0）

- 核对页对可映射的项目提供「写入指标」。映射表示例：空腹血糖 → 血糖（场景=空腹）；体重 → 体重；收缩压/舒张压 → 血压。
- 映射表由产品配置维护，V1.0 至少覆盖第 5.2 节预置指标中出现在常规体检里的项目。
- 写入时使用体检日期作为测量时间，来源为该报告。同一报告重复写入同一项目时覆盖该来源记录，不产生重复点。
- 无法映射的项目只留在报告明细里。

#### RPT-05 跨报告查看（P1）

- 在某一检查项上查看历次结果列表（日期、结果、单位、所属报告）。
- 单位不一致时不直接画在同一条趋势上，提示用户单位不同。
- 已写入指标的项目，以指标趋势为准，此视图作为报告侧的补充。

### 5.4 大模型分析

本章是独立模块，同时被指标页和报告页调用。安全边界见 5.4.4，落地要求见第 7 章。

#### AI-01 分析入口与授权（P0）

入口：

- 首页「看看我的近况」
- 单指标页「分析这段趋势」
- 报告详情「解读这份报告」
- 分析页自行选择范围
- 学习页不默认把全文喂给模型；仅当用户在分析里勾选「结合我正在学的专题」时，发送专题标题与已学进度，不发送整库文章

首次使用分析前，展示单独授权页，说明：

- 会把哪些数据发给模型服务；
- 模型服务的提供方名称；
- 这些数据不用于训练该用户的模型（默认，且在授权文案中写明）；
- 可随时关闭分析能力；
- 分析不能替代医生。

用户未同意时，分析入口仍可见，点击后回到授权页，不发送任何健康数据。关闭分析后，历史分析文本仍留在账户内，直到用户删除。

#### AI-02 指标分析（P0）

- 用户选择：指标（可多选，最多 5 个）、时间范围（7 / 30 / 90 天或自定义，自定义最长 365 天）。
- 发送内容为该范围内的记录摘要：日期、数值、场景、来源。不发送与本次无关的报告和习惯，除非用户另行勾选。
- 输出结构固定为四段，缺数据时明确写「数据不足，无法判断」：
  1. **记录了什么**：条数、时间跨度、最近一次值。
  2. **可以看到的变化**：上升、下降、波动或基本平稳，附关键数值。
  3. **可以考虑的生活安排**：饮食、运动、睡眠、复测频率方面的一般性建议，每条都能对应到上一段的事实。
  4. **建议当面咨询医生的情况**：命中配置规则时置顶展示固定就医提示；未命中时写「本次记录未触发产品内的紧急提示规则」，并提醒规则不能覆盖所有危险情况。

#### AI-03 报告解读（P0）

- 默认输入：该报告已核对的项目、用户档案中的年龄段和性别（若已填）、用户勾选的相关指标（默认勾选与报告项目同名的近 90 天指标）。
- 输出结构：
  1. 这份报告包含哪些类项目；
  2. 报告上标记为异常、或偏离报告自带参考范围的项目列表；
  3. 这些项目通常表示什么（科普口吻，不断言用户患有某种疾病）；
  4. 就诊时可向医生提出的问题；
  5. 依据：项目名称、结果、报告参考范围、关联的个人指标。
- 影像报告若只有描述文字、没有结构化数值，按文字摘要解读，并说明「影像结论请以原件和放射科/超声科报告为准」。

#### AI-04 综合近况（P1）

- 范围固定为近 7 天或近 30 天。
- 可勾选纳入：指标、已核对报告（体检日期落在范围内，或用户指定一份）、习惯完成率。
- 习惯与指标放在一起时，只描述「同期发生」，不写成因果关系。例如允许：「这 30 天记录了 12 次血压，习惯『步行』完成 20 天。」不允许：「因为你步行不够，所以血压升高。」

#### AI-05 追问（P0）

- 每份分析结果下可继续提问，上下文保留该次已授权的数据范围。
- 用户若要求分析范围以外的数据，先追加授权确认，再发送。
- 单次分析会话保留最近 20 轮。更早内容在本会话中折叠，仍可在历史里查看原文。
- 提供「重新生成」。重新生成覆盖展示用的最新一版，旧版留在该次分析的历史中。

#### AI-06 分析历史（P0）

- 列表展示时间、类型、数据范围标题。
- 可打开、删除。删除后不可恢复。
- 分析生成时的数据快照要保存，避免用户事后修改指标导致「依据」对不上。页面注明「依据为生成当时的数据」。

#### AI-07 危急提示规则（P0）

下列规则**不依赖模型发挥**，由产品配置判断，命中后用固定文案置顶，模型不得将其改写成居家治疗方案：

| 条件 | 固定提示要点 |
| --- | --- |
| 收缩压 ≥ 180 或舒张压 ≥ 120 | 建议尽快联系医生或前往急诊，不要根据本产品自行加药或停药 |
| 血氧 &lt; 90 | 建议尽快就医 |
| 体温 ≥ 39.0 | 建议尽快就医 |
| 血糖 ≤ 3.0 mmol/L，或血糖 ≥ 16.7 mmol/L | 建议尽快就医 |
| 用户在症状备忘或提问中出现「胸痛、呼吸困难、一侧肢体无力、口角歪斜、意识不清、大量出血、自杀」等配置词 | 提示立即寻求现场帮助或急诊；若涉及自伤，展示当地紧急心理援助说明（具体号码在上线前按发布地区确认） |

规则命中时，分析接口仍可返回科普内容，但就医提示永远在第一条，且样式与普通建议区分开。

#### AI-08 失败与限额（P0）

- 模型超时（建议 30 秒）或失败时，保留用户已选范围，提供重试。
- 不把模型原始报错直接暴露给用户。
- 为控制成本，单用户每日分析次数设产品配置上限（建议初始 20 次，含追问）。达到上限时说明次日恢复，已生成的历史仍可看。
- 提取报告若走同一模型额度，与「分析次数」分开计数，避免传一份长报告把当天问答额度用完。具体拆分在技术方案中落地，产品要求两者都有上限且分别提示。

### 5.5 健康习惯打卡

#### HAB-01 习惯模板与自定义（P0）

预置模板（可改名、改提醒后再启用）：

- 喝水（计数型，默认目标 8 次，每次可按 200 ml 理解，用户可改目标和单位说明）
- 步行或运动 30 分钟（完成型）
- 23:30 前停止看屏幕（完成型）
- 按自己的用药清单服药（完成型）。文案强调「提醒你执行自己已有的安排」，不推荐药品、不生成剂量。
- 记录一项身体指标（完成型，点击可跳到记一笔）
- 阅读一条健康知识（完成型，点击可跳到今日一条）

自定义字段：名称（20 字）、类型（完成型 / 计数型）、计数目标（1–99）、重复规则（每天，或指定周几）、提醒时间（可关闭）、备注。

单用户同时进行中的习惯最多 30 个。可归档。归档后不再提醒，历史打卡保留。

#### HAB-02 打卡（P0）

- 完成型：点一次完成，再点一次在当日可撤销。
- 计数型：支持 +1 和直接改数字。达到目标即视为当日完成。
- 打卡日按用户本地自然日计算，跨日临界以 00:00 本地时间为准。
- 当日未完成的习惯在首页列出，完成后从待办挪到「今日已完成」。

#### HAB-03 补卡（P0）

- 允许补近 2 个自然日（含当天共 3 天内）。更早日期不可补。
- 补卡记录标记为「补卡」，连续天数计算包含补卡，统计页可看到补卡次数。
- 不提供「一键全勤」。

#### HAB-04 提醒（P1）

- 每个习惯最多 2 个提醒时间。
- 提醒内容只包含习惯名称，不包含健康指标数值，避免锁屏泄露。
- 用户可关闭全部习惯提醒。

#### HAB-05 统计（P0）

- 每个习惯展示：当前连续天数、最长连续、本月完成率、月历（完成 / 补卡 / 未完成）。
- 首页只展示连续天数和今日进度，避免手机首屏过长。
- 连续天数在本地过完一天仍未完成、且已超过可补卡窗口后中断。仍在可补卡窗口内时，连续天数显示为「待补卡」，不直接清零。

### 5.6 健康学习

学习内容由运营配置，V1.0 不做用户投稿。目标是让用户既能每天看到一条短内容，也能沿专题学完一个主题。

#### LRN-01 内容结构（P0）

三级结构：

1. **分类**：饮食、运动、睡眠、体重与代谢、血压与心血管、血糖、体检报告怎么看、用药常识、情绪与压力、季节与传染病预防。分类可在后台增删，前台按配置排序。
2. **专题**：某个分类下的学习路径，有标题、简介、预计总时长、有序章节。
3. **文章**：属于一个或多个专题，也可只属于分类。字段包括标题、摘要（用于 tips）、正文、预计阅读分钟、来源说明、更新时间、审核状态。

正文支持小标题、段落、有序/无序列表、图片。V1.0 不支持视频正文；若后续加入，不改变本章的路径和进度规则。

#### LRN-02 今日一条（P0）

- 首页和学页顶部展示一条短内容：默认取摘要，用户可展开或进入全文。
- 选取顺序：用户进行中的专题的下一篇未读文章摘要 → 用户标记「想多看」的分类 → 全站推荐。同一篇 7 天内不重复作为今日一条。
- 用户可「换一条」「收藏」「标记已读」。换一条最多 5 次/天，之后仍可进分类自行浏览。
- 已读状态与专题进度同步。

#### LRN-03 分类浏览与搜索（P0）

- 分类页展示其下专题和独立文章。
- 搜索范围：标题、摘要、分类名、专题名。V1.0 不做全文搜索以外的语义检索；若实现成本低，可同时搜正文，但搜索结果仍只展示已发布内容。
- 无结果显示推荐专题，不展示空白页。

#### LRN-04 专题学习与进度（P0）

- 专题页展示章节顺序、每章阅读状态、总进度百分比（已读章节 / 总章节）。
- 打开文章即记为「在读」，滚动至文末或点击「完成本节」记为「已读」。以先发生者为准。
- 进度按账户保存在服务端，换手机或换到 PC 后继续。
- 支持「继续学习」，回到最近一篇在读或下一篇未读。
- 用户可同时进行最多 5 个专题。超出时提示先完成或移出进行中，已读记录不丢失。

#### LRN-05 收藏与历史（P1）

- 文章可收藏、取消收藏。
- 「最近阅读」保留 50 篇。
- 收藏和历史只对本人可见。

#### LRN-06 学完一节后的关联（P1）

- 文末可配置「相关动作」：去记录某个指标、去开启某个习惯模板。这是跳转，不自动创建数据。
- 若用户已授权分析，文末可出现「用我的数据分析这个主题」按钮，点击后进入 AI-02，并预选配置好的指标。未授权则进入授权页。

#### LRN-07 内容规范（P0）

每篇文章发布前需要内容侧确认：

- 有来源说明（指南名称、公开科普机构或内部审核记录）；
- 不出现诊断承诺、治愈承诺、具体处方和剂量建议；
- 涉及疾病时写明「了解这些信息后，个人情况请咨询医生」；
- 与产品内危急提示规则不矛盾。

前台文章页脚固定展示内容更新时间与「本内容用于健康科普，不能替代诊疗」。

#### LRN-08 后台内容管理（P0，内部）

运营后台不属于普通用户界面，但属于本期交付：

- 分类、专题、文章的新增、编辑、排序、下线。
- 下线后前台不可再打开，已读进度保留；用户收藏夹中显示「内容已下线」。
- 草稿不对用户可见。

V1.0 后台可做成简单的内部管理页，账号与普通用户体系隔离。

## 7. 大模型能力要求

### 7.1 职责划分

| 事项 | 承担者 |
| --- | --- |
| 是否命中危急规则 | 服务端规则，不交给模型决定 |
| 数值计算（均值、最高、BMI、完成率） | 服务端计算后把结果提供给模型引用，模型不重新口算作为唯一依据 |
| 报告文字和表格的提取 | 可用 OCR + 模型。结果一律视为待核对 |
| 语言组织、科普解释、就诊问题建议 | 模型 |
| 把提取结果写入指标 | 只能由用户在核对页确认 |

### 7.2 输入约束

- 只发送完成当前任务所需的字段。身份标识使用内部用户 ID，不发送手机号、姓名。
- 报告原件图片/PDF 仅在「提取」任务中发送。已经核对过的分析默认只发结构化项目，不再重复传原件。
- 系统提示词（由研发固化，不对用户编辑）至少约束：
  - 使用用户数据中的数字，不编造未提供的检查结果；
  - 不给出诊断名称作为用户的结论；
  - 不推荐具体药品和剂量；
  - 不鼓励停药、换药；
  - 危急规则命中时服从系统插入的固定提示；
  - 数据不足时直接说明不足。

### 7.3 输出约束

- 服务端校验输出是否包含四段结构（指标分析）或第 5 节约定的报告结构。缺失则要求模型按原范围重试一次，仍失败则告诉用户生成失败。
- 对明显幻觉做拦截：输出中的数值若无法在输入快照中找到，该句不展示，并在内部记录以便排查。做不到完整拦截时，页面仍以「依据」列表为准，依据列表只渲染快照中的真实记录。
- 输出使用简体中文。涉及专业名词时括号给出日常说法，例如「低密度脂蛋白（常说的坏胆固醇）」。

### 7.4 可解释性

每条分析展示「依据」：

- 指标：名称、时间范围、条数、服务端计算的均值/极值；
- 报告：报告标题、体检日期、被引用的项目和结果；
- 档案：用到了年龄段或性别时明确写出「使用了你的档案」。

用户可以从依据跳到原始记录或原报告。

## 8. 数据需求

### 8.1 主要对象

| 对象 | 关键内容 | 保留 |
| --- | --- | --- |
| 用户 | 手机号、凭证、档案、单位偏好、授权开关 | 账户存在期间 |
| 指标定义 | 预置或自定义、单位、目标区间、是否隐藏 | 随账户 |
| 指标记录 | 指标、时间、数值或文本、场景、来源、备注 | 随账户，删除后回收站 30 天 |
| 报告 | 元数据、文件、状态 | 随账户 |
| 报告项目 | 名称、结果、单位、参考范围、是否已核对、是否已写入指标 | 随报告 |
| 分析会话 | 范围、快照、消息、模型标识 | 随账户，用户可删 |
| 习惯 | 规则、提醒、状态 | 随账户 |
| 打卡 | 日期、次数、是否补卡 | 随习惯历史 |
| 内容 | 分类、专题、文章、发布状态 | 运营数据 |
| 学习进度 | 用户、文章、状态、时间 | 随账户 |
| 操作记录 | 谁在何时改了哪条健康数据 | 不少于 180 天 |

### 8.2 统计口径

- 「今日」= 用户本地时区的自然日。
- 完成率 = 统计期内实际完成天数 / 应完成天数。未到的未来日期不计入分母。归档前的应完成日仍计入。
- 连续天数按应完成日计算。习惯若设为仅工作日，则周末不中断连续。
- BMI 保留 1 位小数。血糖保留 1 位小数。血压、心率为整数。

### 8.3 导出（P1）

- 用户可导出：档案、指标记录（CSV）、习惯与打卡（CSV）、已核对报告项目（CSV）、分析文本（Markdown 或 PDF 中的一种，V1.0 至少 Markdown）。
- 报告原件打包为 ZIP。
- 导出文件生成后提供限时下载，过期删除。导出动作记入操作记录。

## 9. 非功能需求

### 9.1 性能

| 场景 | 要求 |
| --- | --- |
| 首页首屏（已登录，常规数据量） | 4G 手机网络下 3 秒内可操作 |
| 保存一条指标 | 服务端成功响应后界面 1 秒内更新 |
| 指标趋势（单指标 365 条以内） | 2 秒内完成绘制 |
| 报告上传反馈 | 1 秒内出现进度，不阻塞继续浏览已有报告 |
| 分析首字或完整结果 | 30 秒内返回；超时进入可重试状态 |
| 报告提取 | 10 页以内的 PDF 在 60 秒内给出待核对结果或明确失败 |

常规数据量按单用户指标记录 2 万条、报告 200 份设计。超过时列表必须分页，禁止一次拉取全部。

### 9.2 可用性与兼容

- PC：Chrome、Edge、Safari 最近两个大版本。
- 手机：iOS Safari 最近两个大版本，Android Chrome 最近两个大版本。
- 宽度：320px 至 1440px 为验收区间，大于 1440px 内容区居中，不无限拉宽正文。
- 关键操作支持键盘完成（PC）：表单回车保存、对话框可关闭。
- 图片需要替代文本；状态不只靠颜色表达。
- 视觉验收执行 4.4，重点看 UI-02、UI-07、UI-08、UI-10。

### 9.3 可靠性

- 指标、打卡、核对结果以服务端为准。本机离线队列只作发送前缓冲。
- 报告文件上传成功但提取失败时，文件必须已经持久保存。
- 每日自动备份业务数据库和对象存储，保留策略在技术方案中规定，产品要求至少能恢复到近 7 天内的某一天。

### 9.4 可观测

需要能按天查看：注册成功、记录条数、报告上传成功/提取失败、分析成功/失败/超时、打卡次数、文章阅读完成。不在日志中打印指标数值、报告正文和提问原文。

## 10. 隐私、安全与合规

健康信息按敏感个人信息对待。

- 采集前说明用途。手机号用于登录；档案用于计算和展示；报告和分析用于用户主动发起的管理与解读。
- 「发送数据给大模型」使用单独开关，默认关闭，直到用户在 AI-01 同意。
- 传输使用 HTTPS。报告和数据库中的健康字段加密存储。具体算法在技术方案确定。
- 报告文件使用私有地址，每次预览使用短期有效链接。
- 用户可导出（第 8.3 节）和删除账户。删除账户需再次验证手机号，并明确告知：指标、报告原件、分析、习惯、学习进度将被删除且不可恢复。验证通过后 7 天内完成从线上存储和备份周期中的清除；这 7 天内用户可撤销删除。
- 日志、监控、崩溃报告中不记录健康数值和报告内容。
- 模型供应商协议需满足：默认不将用户内容用于训练；数据保存期限可查询。供应商名称在授权页和「我的 - 隐私」中可见。
- 后台运营账号与用户数据权限分离。运营可管理学习内容，不能查看用户指标和报告，除非另有带审批的排障流程。V1.0 可以先做到后台无入口，排障走数据库审批。
- 免责声明出现在：首次启动、分析授权页、分析报告页脚、文章页脚。文案要点一致：本产品用于个人记录和健康科普，不提供诊疗，不适或紧急情况请联系医疗机构。

上线前由合规确认发布地区的告知文本、自伤相关求助信息、以及健康数据跨境（若模型服务不在境内）的单独同意文案。需求上预留这些文案的配置位，不把法务文本写死在代码里。

## 11. 异常与边界

| 情况 | 产品行为 |
| --- | --- |
| 未填身高却记录体重 | 保存体重，BMI 显示「补充身高后可计算」 |
| 血糖未选场景 | 不能保存 |
| 报告 0 字节或加密 PDF | 提示无法读取，请上传未加密文件或改为图片 |
| 提取结果明显串行 | 用户在核对页修改；在确认前不影响指标曲线 |
| 模型返回诊断式结论 | 整段不展示，提示生成失败并允许重试 |
| 同一天两台设备同时打卡 | 完成型以已完成为准；计数型合并为较大值，若差值来自同时编辑则保留较大值并记一条操作记录 |
| 提醒权限被拒绝 | 习惯和指标仍可手动完成；设置页保持「去开启」 |
| 文章下线 | 进度保留，前台不可读，收藏中标注已下线 |
| 用户关闭分析授权 | 立即停止新的模型请求；历史分析仍可阅读和删除 |
| 时区变更 | 新的「今日」按新时区；已写入的打卡日期不回溯改写 |

## 12. 验收标准

下列条目用于 V1.0 验收。每条在手机宽度（390px）和 PC 宽度（1280px）各测一遍，数据结果应一致。

**账户**

- 新用户用手机号完成登录，跳过档案后仍能记下一条体重。
- 补全身高后再记体重，能看到 BMI。
- 退出后重新进入，原浏览器中看不到上一个账户的指标和报告。

**指标**

- 记录血压后，当前设备首页和趋势立即出现该条。
- 收缩压小于舒张压时无法保存。
- 收缩压 185 保存成功，页面出现建议尽快就医的固定提示。
- 编辑一条历史体重后，该条 BMI 按当时身高重算，其他日期不变。
- 自定义一个「腰围目标」之外的数值指标并成功记录（若 P1 纳入本迭代）。

**报告**

- 上传一张清晰化验单图片和一份未加密 PDF，两者都出现在列表中并可预览。
- 解析失败的文件仍可下载、可删除、可改标题。
- 核对并确认后，把空腹血糖写入指标，指标曲线出现来源为该报告的点，点击可回到报告。
- 删除报告时选择保留指标，指标还在，来源跳转变为「原报告已删除」。

**分析**

- 未授权时发起分析，不会产生模型请求（可通过网络记录或服务端日志验收）。
- 授权后对近 30 天血压生成分析，页面包含记录摘要、变化、生活建议、就医相关说明和依据。
- 依据中的数值能在指标列表中找到。
- 对已核对报告生成解读，异常项与核对表一致，不出现核对表里没有的检查数值。
- 血氧 88 的记录存在时，分析结果第一条为固定就医提示。
- 删除某次分析后，列表中不再出现。

**习惯**

- 从模板启用「步行或运动 30 分钟」，当日打卡后连续天数为 1，首页待办消失或变为已完成。
- 撤销当日打卡后恢复为未完成。
- 对昨天补卡，标记为补卡，且前天以前超过窗口的日期无法补。
- 计数型喝水达到目标后，当日状态为完成。

**学习**

- 分类下能打开专题和文章。
- 读完第一节后进度变化；换浏览器登录同一账户，进度相同，并能从「继续学习」进入下一节。
- 今日一条可换一条、可进入全文、已读后不再把同一篇立刻重复推荐。
- 下线一篇已读文章后，进度仍在，打开链接时看到已下线说明。

**多端与界面**

- 手机完成的记录、打卡、阅读进度，PC 刷新后可见。
- 在 320、390、768、1024、1280、1440 宽度下打开首页、记一笔、指标详情、报告详情、习惯、文章：导航和主按钮完整可见，文字不重叠、不溢出，页面本身没有横向滚动。
- 手机首页一屏内能分清最近指标数字、今日待打卡、今日一条，主操作落在拇指可及区域，且不被底部导航挡住。
- PC 首页同时看到概览和趋势，内容区不过度拉宽；报告详情可以同时看到原件区域和提取结果区域。
- 指标数字、单位、状态标签能分开读出。状态在浅色和深色下都有文字，不只靠颜色。
- 抽查登录、首页、记一笔、文章四页：间距、圆角、主色与 4.4 的设计基线一致，空状态有说明和主操作。
